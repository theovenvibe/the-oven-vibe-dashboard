# reviews/

Weekly reviews written by the `weekly-review` skill (`.claude/skills/weekly-review/`).

## Convention

- One file per review: `YYYY-MM-DD.md`, dated the day the review was run.
- Files are append-only history, never edited after the fact — if a plan
  changed mid-week, that shows up in the *next* review's "follow-up" section,
  not as an edit to an old file.
- Sort by filename for chronological order (oldest first, lexically).
- Each review is generated from `weekly_brief.md` at the repo root, which is
  itself regenerated by `uv run build.py` from the warehouse. A review file
  is a snapshot in time, not a live document — re-running the skill later
  produces a new dated file, it does not update an old one.

## What's inside a review

Summary, what changed since the prior week, a ranked plan of action for the
coming week, and a follow-up on whether last week's plan actually got
actioned. See `.claude/skills/weekly-review/SKILL.md` for the exact
structure the skill produces.

## Reading history

To see how the restaurant's numbers and the owner's decisions evolved,
read the files in order. Each review's follow-up section links its plan
back to the previous week's, so the sequence of files doubles as an
audit trail of what was tried and what changed after.
